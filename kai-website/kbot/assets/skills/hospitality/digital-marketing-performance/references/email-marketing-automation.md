# Email Marketing Lifecycle, Automation & Deliverability

## Parte 1: Email Marketing Lifecycle

### Email Lifecycle Overview

```
Customer Journey:
Pre-purchase → Post-purchase → Retention → Churn risk → Win-back

Email campaigns allineate:
1. Welcome Series (Day 0-14) → Activation + educazione
2. Abandoned Cart (Day 0-3) → Conversione immediata
3. Post-Purchase (Day 1-30) → Delight, reduce returns
4. Engagement (Ongoing) → Education, promotion, nurture
5. Win-Back (Day >90 inattività) → Re-engage dormant users
6. Unsubscribe Preference (Soft exit) → Ridurre hard unsubscribe
```

## Parte 2: Email Deliverability (SPF, DKIM, DMARC)

### SMTP Authentication: SPF, DKIM, DMARC

```
Problema: Email spoofing (attacker invia email from your domain)
Soluzione: Autenticazione protocolli SPF, DKIM, DMARC

┌─────────────────────────────────────────────────────┐
│ Email Sending Flow:                                  │
│                                                      │
│ 1. Sender: gmail@yourdomain.com → Email content     │
│ 2. SMTP server: validate SPF, DKIM, DMARC           │
│ 3. Recipient ISP: check SPF ✓, DKIM sig ✓, DMARC✓  │
│ 4. Inbox: delivery (authentication passed)          │
│    OR Spam: (authentication failed)                 │
└─────────────────────────────────────────────────────┘
```

### SPF (Sender Policy Framework)

**Funzione:** Autorizza IP-address per spedire email dal tuo dominio

**Setup:**
```
DNS TXT Record: yourdomain.com

v=spf1 include:mailchimp.com include:sendgrid.net ~all

Significato:
- v=spf1 → SPF versione 1
- include:mailchimp.com → Mailchimp autorizzato a spedire
- include:sendgrid.net → SendGrid autorizzato
- ~all → Soft fail (accetta altri server, ma contrassegna)
- -all → Hard fail (rifiuta altri sender - RIGOROSO)

Best practice: ~all (morbido) per testing, poi -all quando stabile
```

**Validation:**
```bash
nslookup -type=TXT yourdomain.com
# Output: v=spf1 include:mailchimp.com ~all
```

---

### DKIM (DomainKeys Identified Mail)

**Funzione:** Crittografico firma email (public key in DNS, private key su server)

**Setup Flow:**

```
1. Email service (Mailchimp) genera DKIM key-pair
2. Public key publishato in DNS record
3. Email spedita con private key signature
4. Recipient ISP verifica firma con public key
5. Se firma valida → Email not tampered, authentic
```

**DNS Record (CNAME):**
```
CNAME: default._domainkey.yourdomain.com → 
       dkim.mcdlv.net (Mailchimp example)

OU

TXT Record (full public key):
default._domainkey.yourdomain.com TXT "v=DKIM1; k=rsa; p=[PUBLIC_KEY_BASE64]"
```

**Validation:**
```bash
# Check DKIM record
dig default._domainkey.yourdomain.com TXT

# Output: v=DKIM1; k=rsa; p=MIGfMA0... (public key)
```

---

### DMARC (Domain-based Message Authentication, Reporting & Conformance)

**Funzione:** Policy che combina SPF + DKIM, definisce azione se fallanno (reject, quarantine, none)

**Setup:**
```
DNS TXT Record: _dmarc.yourdomain.com

v=DMARC1; p=none; rua=mailto:dmarc@yourdomain.com

Significato:
- v=DMARC1 → DMARC versione 1
- p=none → Policy "none" (monitor, non reject - testing phase)
- p=quarantine → Quarantine if fail (spam folder)
- p=reject → Reject if fail (bounce email - RIGOROSO)
- rua=mailto:... → Report URI aggregate (weekly report)
- pct=100 → Apply policy to 100% mail (default)

Progression:
1. Week 1-4: p=none (monitor DMARC failures)
2. Week 4-8: p=quarantine (soft filter spam folder)
3. Week 8+: p=reject (hard filter, safest)
```

**DMARC Report Example:**
```
Weekly aggregate report:
- Total email sent: 10,000
- SPF pass: 9,950
- SPF fail: 50
- DKIM pass: 9,950
- DKIM fail: 50
- Overall pass (SPF OR DKIM): 9,950
- Overall fail (SPF AND DKIM fail): 50
```

## Parte 3: Email Sender Reputation & Spam Triggers

### Sender Reputation Metrics

| Metrica | Fonte | Range | Target | Impatto |
|---------|------|-------|--------|---------|
| **IP Reputation Score** | ISP (Gmail, Outlook, Yahoo) | 0-100 | >80 | Deliverability |
| **Domain Reputation** | ISP | 0-100 | >80 | Deliverability |
| **Bounce Rate** | Email platform | % | <3% | Sender score ↓ se >5% |
| **Complaint Rate** | ISP (spam button clicks) | % | <0.1% | Spam folder se >0.5% |
| **Unsubscribe Rate** | Platform | % | <0.5% | Normal (>1% = content issue) |
| **Engagement Rate** (open + click) | Platform | % | >10% | Positive signal to ISP |

### Spam Triggers Checklist

| Categoria | Trigger | Impact | Fix |
|-----------|---------|--------|-----|
| **Content** | "Free money", "Act now!", excessive caps | Spam filter | Professional copy, avoid jargon |
| | Too many links (>5 per email) | Spam filter | Limit links, prioritize 1-2 CTA |
| | Images-only email (no text) | Spam filter | 60% text, 40% image ratio |
| | Suspicious domains (bit.ly shortened URLs) | Spam filter | Use branded links only |
| **Sender** | Unknown sender IP (new IP) | Warmup phase needed | Gradual ramp (see IP warmup) |
| | Sender name mismatch (from: gmail@corp.com, not company rep) | Spam filter | Use "Company <noreply@company.com>" format |
| | No reply-to address | ISP sees suspicious | Set reply-to to support@company.com |
| **Authentication** | Missing SPF/DKIM/DMARC | High spam probability | Implement all three |
| | DMARC fail rate >5% | Deliverability ↓ | Monitor DMARC report, fix sources |
| **List Hygiene** | Invalid email addresses | Bounce rate >5% | Validate addresses before sending |
| | Spam trap emails (honeypot) | Blacklist risk | Use double opt-in, remove inactive |
| | Too many unsubscribes (>2%) | ISP flag | Content/frequency issue |

### IP Warmup Strategy (New Sending IP)

**Scenario:** Launching new email server IP (e.g., migrating ESP)

```
Phase 1 (Week 1):
- Volume: 100-500 emails/day
- Target: Engaged, recent openers only
- Monitor: Bounce rate, complaint rate
- Expected: 0-1% spam complaint

Phase 2 (Week 2-3):
- Volume: 1,000-5,000 emails/day
- Target: All subscribers (engaged first)
- Ramp: Increase 50% per day
- Monitor: Bounce rate <2%, complaint <0.1%

Phase 3 (Week 4-6):
- Volume: Full list send
- Target: All segments
- Ramp: Gradual increase
- Expected: Normal deliverability

Phase 4 (Week 6+):
- Full volume
- All list segments
- Normal monitoring

IP Warmup Spreadsheet:
| Week | Day | Daily Volume | Cumulative | Bounce Rate | Complaint |
|------|-----|---|---|---|---|
| 1 | 1-7 | 500 | 3,500 | <2% | <0.1% |
| 2 | 8-14 | 2,500 | 21,000 | <2% | <0.1% |
| 3 | 15-21 | 5,000 | 56,000 | <2% | <0.1% |
| 4+ | 22+ | Full list | 500,000+ | <2% | <0.1% |
```

## Parte 4: Email Performance Metrics & Benchmarks

### Core Email KPIs

| KPI | Formula | B2C Benchmark | B2B Benchmark | Interpretazione |
|-----|---------|---|---|---|
| **Delivery Rate** | (Delivered / Sent) × 100 | 95-99% | 95-99% | Softbounce + hardbounce; <95% = list quality issue |
| **Open Rate** | (Unique opens / Delivered) × 100 | 20-30% | 15-25% | Higher = good subject line, timing, sender reputation |
| **Click-Through Rate (CTR)** | (Unique clicks / Delivered) × 100 | 2-5% | 1.5-3% | Higher = relevant content, clear CTA |
| **Click-to-Open Rate (CTOR)** | (Clicks / Opens) × 100 | 10-20% | 8-15% | Email content quality (aside from open) |
| **Conversion Rate** | (Conversions / Delivered) × 100 | 1-3% | 0.5-2% | Revenue impact |
| **Bounce Rate** | (Bounces / Sent) × 100 | <3% | <3% | >3% = list decay, invalid addresses |
| **Unsubscribe Rate** | (Unsubscribes / Delivered) × 100 | <0.5% | <0.3% | Normal; >1% = content, frequency issue |
| **Spam Complaint Rate** | (Spam reports / Delivered) × 100 | <0.1% | <0.1% | CRITICAL: >0.5% = ISP blacklist risk |

### Open Rate vs. Subject Line Testing

**Factors affecting open rate:**
```
Subject line (40-50% impact)
├─ Length: 50 char ideal
├─ Personalization: [First name] +10-20% open rate
├─ Power words: "Discover", "Urgent", "Limited time"
├─ Emoji: Mixed results (+5-15% open or -10% if overused)
│
Sender name (20-30% impact)
├─ Known sender (company name) better than noreply
├─ Person name (e.g., "John from Marketing") +5% vs company
│
Send time (15-25% impact)
├─ B2C: Tuesday-Thursday 10am-2pm, 6-9pm
├─ B2B: Tuesday-Thursday 8-10am
│
List quality (15-20% impact)
├─ Recent subscribers > old list
├─ Engaged segment > cold segment
```

**Subject Line A/B Test Example:**

| Version | Subject Line | Opens | Open Rate | Winner |
|---------|---|---|---|---|
| A | "New product alert" | 450 | 18% | - |
| B | "[Name], discover our newest collection" | 520 | 20.8% | ✓ +2.8% |
| C | "⚡ Limited time offer: 48 hours only" | 580 | 23.2% | ✓✓ +5.2% |

**Winning formula:** Personalization + urgency + clear benefit

### Dynamic Segmentation & A/B Testing

**Segmentation Approach (Behavioral):**

```
Segment 1: "High-intent buyers" (score >60)
├─ Last email open <7 days ago
├─ Clicked pricing page
├─ Downloaded comparison
└─ Campaign: Sales demo nurture

Segment 2: "Engaged but not sold" (score 40-60)
├─ 2+ email opens last month
├─ No pricing page visit
└─ Campaign: Educational, product showcase

Segment 3: "Dormant" (score <20, no open 30+ days)
├─ Win-back campaign (50 point re-engagement offer)
└─ Or: Remove if score <10 after 90 days
```

**Email A/B Testing: Statistical Rigor**

```
Test variable: Subject line (two versions)
Sample size calculation:

n = 2 × [(Z_α/2 + Z_β) / MDE]²

Where:
- Z_α/2 = 1.96 (95% significance, α=0.05)
- Z_β = 0.84 (80% power, β=0.20)
- MDE = 2% (minimum detectable effect = 2 point open rate lift)

n = 2 × [(1.96 + 0.84) / 0.02]²
  = 2 × [140]²
  = 39,200 emails per variation

Praktická: Split 10,000 emails (5,000 each), accept ±15% margin error
Time: Run 1 day (24 hours), check results

Decision rule:
- p-value <0.05 → Significance, winner clear
- p-value 0.05-0.10 → Inconclusive, test longer
- p-value >0.10 → No winner, inconclusive
```

## Parte 7: Email Deliverability Playbook (Checklist)

### Pre-Campaign Checklist

- [ ] **List Hygiene**
  - [ ] Remove hard bounces (non-existent addresses) from previous campaigns
  - [ ] Remove unsubscribes from all previous campaigns
  - [ ] Remove spam complaints from previous campaigns
  - [ ] Validate email addresses (tool: ZeroBounce, NeverBounce)
  - [ ] Target: Bounce rate <3%, complaint <0.1%

- [ ] **Authentication**
  - [ ] SPF record published in DNS (v=spf1 include:[ESP] ~all)
  - [ ] DKIM public key in DNS (_domainkey TXT record)
  - [ ] DKIM selector configured in ESP (e.g., default._domainkey.yourdomain.com)
  - [ ] DMARC record published (_dmarc.yourdomain.com with p=quarantine)
  - [ ] Monitor DMARC report weekly for failures

- [ ] **Sender Reputation**
  - [ ] Sender email: [noreply@yourdomain.com] (matching domain)
  - [ ] Reply-to email: [support@yourdomain.com] (valid)
  - [ ] Sender name: "Company Name" or "John from Company"
  - [ ] Subject line: No spam trigger words (FREE MONEY, ACT NOW)
  - [ ] No excessive links (limit to 5 max)

- [ ] **IP & Domain Warmup**
  - [ ] If new IP: Gradual ramp (see IP warmup section)
  - [ ] If new domain: Start with engaged list only
  - [ ] Monitor bounce + complaint rates (should stay <3%, <0.1%)

- [ ] **Content Quality**
  - [ ] Alt text for all images
  - [ ] 60% text, 40% images ratio
  - [ ] Mobile responsive design
